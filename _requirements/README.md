# MC Requirements System

A structured documentation framework for building products. The installer (`scripts/mc/scaffold-core.js`, run by `/mc:setup`, `install.ps1` and `/mc:update`) creates the folder skeleton below in every product, each folder with a `.gitkeep`; `/scan:mc-structure-parity` checks that every skeleton folder exists.

## Structure

| Folder | Purpose | Files in this repository |
|--------|---------|--------------------------|
| `_standards/` | Spec-writing standards and templates | PRD_TEMPLATE, HIGH_LEVEL_STORIES, GRANULAR_STORIES, STORIES-COMMON, INPUTS_TEMPLATE, REVIEW_PROCESS |
| `_audits/` | Systematic review reports | AUDIT_TEMPLATE |
| `_index/` | The requirements graph `requirements.graph.json`, generated by `scripts/requirements/graph-build.js` | — |
| `_shared/` | Requirement fragments that several spec docs reference | README |
| `00-canonical/` | Product foundations: core brief, product model, glossary, golden paths | — |
| `01-design-system/` | UX principles, colours, components | — |
| `02-copy-system/` | Voice, tone and microcopy | — |
| `03-architecture/` | Stack, data flow, security | — |
| `04-features/` | Feature specs, one folder per feature | — |
| `05-operations/` | Deployment and monitoring | — |
| `06-security/` | Security review and red-team reports | — |
| `07-testing/` | Test strategy and the recurring bug-class registry | recurring-bug-classes.json |
| `08-automation/` | CI/CD and scheduled tasks | — |
| `09-integrations/` | Third-party provider notes | — |
| `10-contracts/` | The artifact-contract spec (`paths.contractsSpec`) | ARTIFACT-CONTRACTS |

`_standards/` through `08-automation/` are the structure-parity skeleton. `09-integrations/` is created from the paths registry (`paths.integrationsRoot`).

## How to Use

1. For each feature, create a folder in `04-features/` with PRD.md, COPY.md, HL-STORIES.md, STORIES.md and INPUTS.md, written to the templates in `_standards/`
2. For a systematic review, copy `_audits/AUDIT_TEMPLATE.md` and follow its `<!-- GUIDANCE: -->` comments
3. Put a fragment that several spec docs share in `_shared/`, so it changes in one place

## Resolution Cascade

Write specs top-down: PRDs first (all features), then HL-Stories (all features), then Granular Stories (all features). This prevents inconsistencies between features.
