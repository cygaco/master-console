# ADR-0033 — Brokered transport + live fence (making the sole-route actually LIVE)

**Status:** Accepted (D-4 INC-1, SP-20260721-001, 2026-07-21). **Extends:** ADR-0032 (trusted-enforcement-adapter sole-integration-principal). **Closes:** ED-controller-no-live-release-transport. **β:** DECIDE B/0.89 (plan→design + scope) · B/0.92 (design→build recognizer). **Class:** B.

## Context
ADR-0032 established the trusted-controller as the sole integration principal and shipped the Seam-E `reference-transaction` hook (FIX-3) that refuses any un-brokered write to `refs/heads/main`. But the controller's `integrate()` was UNIT-shaped (workorder / result_envelope / expected_checks / lease + a pinned-suite over a builder's result_commit). It had NO shape for the two write kinds a release actually needs — a BRANCH-MERGE onto main and a routine RELEASE-COMMIT. So the hook could never go live: arming it would brick the release ceremony (`release-canonical.js` ff-merge), the `commit/land` skill, α's sprint-close merges, and manifest-regen/bookkeeping commits — and fabricating a unit envelope for a merge would be false-green genesis (α + β rejected it). The mechanism was verified-but-not-live-wired (ED-controller-no-live-release-transport).

## Decision
Add TWO purpose-built brokered entrypoints over ONE shared fenced-CAS choke-point, then arm the fence only at a mechanically-proven completeness point.

1. **`fencedRefUpdate(newHead, target_ref, opts)`** — the ONE fenced-CAS site. RE-RESOLVES `expectedHead` live from `target_ref` (never a caller anchor — the R1 TOCTOU closure, same class as the Phase-4 S2 fix); materializes `newHead`'s tree BY that exact SHA and runs the pinned suite RUNNER-ISOLATED over it (checked===landed, ADR-0028); resolves the CURRENT conductor-lease token FRESH (never caller-asserted) → `withControllerFence` → atomic CAS `update-ref target_ref expectedHead→newHead`. Fail-closed on suite-fail / no-live-head / lease-not-held / CAS-race.
2. **`integrateBranchMerge`** (first-parent === live head; second parent = provenance only, NOT a trust guard) and **`integrateReleaseCommit`** (single parent === live head) — both thin, both call ONLY `fencedRefUpdate`.

## How the fence goes LIVE (the load-bearing part)
- **The flip-trigger is a MECHANIZED caller-migration enforcer, not a hand-census.** `scripts/checks/main-write-broker-completeness.js` statically scans `scripts/**` + `.claude/commands/**` and asserts ZERO un-brokered local-main-write call-sites (each: a brokered entrypoint | a migrated caller | an allowlisted α-hand/holds-lease writer). It is DISTINCT from `write-surface-delegation-completeness.falsifier` (which proves the MECHANISM refuses un-brokered writes on scratch repos, NOT that the real callers are migrated) — conflating them is a false-green.
- **Recognizer contract (β design→build FOLD 1):** markdown-aware (inline-code + numbered-list skill steps, not just fenced/JS), variable-ref-aware (`$DEFAULT`/`$DEFAULT_BRANCH`/`origin/main`/`HEAD:main`), and conservative (flag any skill that selects `$DEFAULT`/main then merges/commits/update-refs — false-positive over false-negative). Grounded in `commit/land.md:33` (`git merge --no-ff $BRANCH` while on `$DEFAULT`), which a naive literal-`refs/heads/main` scanner would MISS.
- **Named ceiling + hook backstop (FOLD 2):** a static scan CANNOT enumerate variable-ref / prose-embedded / dynamically-constructed main-writes. "Enforcer FIRST-green" therefore means "no KNOWN un-brokered writer remains" (pre-flip BREAKAGE-PREVENTION), NOT "provably every writer migrated." The live reference-transaction hook is the RUNTIME BACKSTOP — it refuses ANY un-brokered main-write at runtime, seen-by-the-scan-or-not; a scan miss ⇒ that writer breaks fail-closed at first post-flip use (discoverable), never a silent land. Division of labor: **static scan = pre-flip breakage-prevention; hook = runtime security boundary.**
- **Dogfood-before-arm + fallback-visibility (α rider + β rider-on-the-rider):** post-INC-1 D-4 merges route through the broker VOLUNTARILY (ordinary route as pre-flip fallback), so the fence arms a transport with REAL mileage (real trees, real divergence, real Windows path/encoding edges a synthetic falsifier misses), not a fresh one. Every pre-flip fallback is LOGGED/COUNTED/SURFACED — a silent fallback = the transport bypassed instead of exercised = an unbacked "proven" claim; zero-or-explained fallbacks by flip time is the honest bar. Mileage is corroborating de-risking evidence; the flip-trigger stays enforcer-green, NOT "dogfood feels sufficient."

## Scope / sequencing (β Option-B)
INC-1 ships the transport + the D-4-owned migrations (α-merge path, regen/bookkeeping) + the mechanized enforcer. The release-ceremony (`release-canonical`) and `commit/land` migration AND the actual hook install/flip DEFER to the release ceremony (task #3, which owns those writes); the flip fires the moment the enforcer FIRST goes green, at a merge-quiet boundary, explicitly announced to α, no bypass envs. ED-controller-no-live-release-transport stays OPEN with that flip-trigger until it fires (guards premature-flip AND deferral-decay). `commit/land` migration is pre-flip-safe (works unbrokered pre-flip AND via the broker post-flip).

## Consequences
Positive: the sole-route becomes actually LIVE without bricking the release pipeline; the trust spine (re-resolved anchor / checked===landed / fresh-lease fenced CAS) is reused, not duplicated; the flip decision rests on a mechanized, non-rotting green + evidenced mileage, not a hand-census or an over-read completeness claim. Residual: the static-scan false-negative ceiling (named, backstopped by the runtime hook) and the honest hostile-shell ceiling (hooksPath redirect / hook deletion / direct .git/refs write / forged env — operator-dropped, out of scope) both persist by design.
