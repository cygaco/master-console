## Two manifests

- **Shipping manifest** = `.claude/framework-manifest.json`, generated by `scripts/generate-framework-manifest.js`. Classifies every *shippable* asset by kind with sha256. Consumed by the installer (`warp-setup.js`): "if a file isn't in the manifest, the installer doesn't see it." Schema `warpos/framework-manifest/v2`, 1349 assets.
- **Ownership manifest** = `_warpos/MANIFEST.json`, generated by `scripts/warpos/manifest/build.js` (SP-20260522-001). Classifies each path's **owner** (framework | generated | project | runtime) to drive `/warp:update` merge strategy. Schema `warpos/manifest/v1`, validated by `scripts/warpos/manifest/validate.js`.

**Regen-both discipline enforcers:**
- **Commit-time (MECH-NEUTRAL):** `scripts/hooks/framework-manifest-guard.js` PreToolUse hook (`settings.json:46`) **blocks** the git commit in canonical if the shipping manifest is stale/unstaged (warn-only when `.claude` gitignored in a product).
- **Release-time (MECH-NEUTRAL):** `release-gates.js` gates `framework_manifest`, `ship_coverage`, `version_coherence` — fire only during release stage 7.
- **Ownership manifest** = `manifest/validate.js --strict`, tied to BC-02 (`validate.js:101`).

**BC gate classes:** BC-02 = manifest coverage/honesty drift · BC-05 = stale-manifest release (T-183) · BC-28 = sealed-capsule reach-back (`sealed_capsule_contract`, `release-gates.js:642`).

**What breaks when someone forgets:** "downstream always missing something" — asset lands in canonical but not the shipping manifest → installer never copies it; OR the manifests disagree on ownership → `/warp:update` clobbers user files or skips real updates. **Asymmetry:** only the shipping manifest is commit-gated; the ownership manifest regen relies on release gate + discipline.

## Bypass analysis

- **Commit with drifted shipping manifest:** BLOCKED by `framework-manifest-guard` — unless `WARPOS_MANIFEST_GUARD=off` or `.claude` gitignored. MECH-NEUTRAL logic, Claude-hook trigger.
- **Ship a release with drifted metadata:** stage-7 gates catch it — BUT `/warp:release` + `release-gates.js` honor `--skip <gate>` (`release.md:16`). A helm can skip any gate. **Primary bypass.**
- **WARPOS.md / RELEASES.md-summary drift:** NOT gated at all — PROSE-only (live 0.14.0 header + placeholder summaries prove it).
- **Ownership manifest staleness:** release-gate only; not commit-gated (asymmetric).
- **Portfolio staleness:** completely unenforced.
