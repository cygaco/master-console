## What we did (ELI5)

**The goal:** our other projects (the other portfolio products) each keep a complaint file about problems they hit with WarpOS, the shared engine they all run on. Fixing a problem inside one project doesn't help the others — it has to be fixed once, here, at the source. Today's job was to read all five complaint files, check which complaints are still true, fix the real ones, and then keep going on the roadmap.

**Checking before fixing (this mattered a lot):** of the 52 complaints, most were already fixed — the projects were just running old copies of the engine and didn't know. Only 14 were still real. By checking first, we avoided wasting hours "fixing" things that weren't broken.

**The big fixes, in plain words:**
- **The toolbox now actually ships.** WarpOS told its projects "you must use this specific tool to launch builder agents safely" — but never included that tool in the box it ships to them. Every project hit a dead end. The tool now ships, and we built a watchdog that checks nothing like this can happen again (the watchdog immediately found and fixed a second missing tool we didn't know about).
- **Projects can finish their work cycles again.** The "close out a work sprint" step demanded a quality-checker module that, by design, is never sent to projects — so no project could ever finish a sprint. Now it checks "am I the home base or a customer project?" before demanding it.
- **Agents stop quietly running on the wrong brain.** Several agent job descriptions said "use whatever AI model the current session happens to use" instead of their assigned one. They're all pinned now, and a checker fails loudly if anyone un-pins one. When we made that checker strict, it instantly found four more agents nobody knew were unpinned.
- **No more frozen managers.** A long-standing bug made our sprint-manager agent wait forever for work that had already finished (it believed someone would wake it up; nobody ever does). The rules are rewritten, and a new detector raises a flag when a manager has been sitting on finished work too long.
- **The "company org chart" is followed by default.** The sprint pipeline used to quietly let the orchestrator do the whole design team's job alone. In sprint mode it now routes work through the proper team by default.
- **Deep research works again.** The research command used techniques our security system rightly blocks, so it could never run. It's rebuilt as a proper standalone program, and it now checks "does this API key actually have money on it?" *before* starting, instead of failing an hour in.
- **Green lights must be earned.** This was the roadmap epic work: a work phase can no longer count as "done" just because a log line says so — there must be a real receipt that an agent actually ran. And the receipt-checker can no longer be fooled by old receipts from past work (two sneaky loopholes were found by reviewers and closed, both proven with live reproductions).

**How the work was checked:** every batch was reviewed by AI reviewers from a *different* company than the one that wrote the code (different blind spots). This earned its keep all day: reviewers caught six real bugs across the batches — including two "the checker itself could be fooled" holes — and every one was fixed and re-reviewed before shipping. The team also ran honestly: our sprint manager caught one of its own tasks being filed under an already-closed project and fixed the paperwork, and refused to build one assignment after discovering it was already done.

**What's different now:** all five projects get these fixes automatically with the next engine update; the engine's own progress reports are much harder to fake; and the research command is usable.
