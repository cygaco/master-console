# WarpOS 0.5.1 — `/product:bootstrap` first-command skill

Drafted: 2026-05-13
Status: draft — pending release

A first-command skill that produces a thorough product brief in MD/HTML
(and DOCX when pandoc is installed) from a short guided discussion.
Intended as the first command an operator runs in a new project.

## Added

### Skill

- `/product:bootstrap` — bootstraps a thorough product brief from a guided
  discussion. Walks through 4-8 questions covering problem, jobs-to-be-done,
  value chain, competitive landscape, wedge, vision, wedge-to-full-vision
  arc, and MVP. Emits MD + HTML (always) and DOCX (when pandoc is on PATH)
  to `paths.briefs` (`_docs/briefs/<slug>/`).

### Namespace

- `/product:` — new top-level skill namespace. Reserved for product-level
  bootstrapping, scoping, and strategy commands. Approved under
  `AP-20260513-003`.

### Files

- `.claude/commands/product/bootstrap.md` — skill manifest with frontmatter
  description and operator-facing usage.
- `scripts/product/bootstrap.js` — orchestrator: CLI, discussion budget
  enforcement, coverage QC, MD/HTML/DOCX writers, paths.json registration,
  re-run versioning, TRACE event emission.
- `framework/templates/product-bootstrap/brief.md.tmpl` — MD template with
  stable `## NN — <Title>` heading convention.
- `framework/templates/product-bootstrap/brief.html.tmpl` — single-file HTML
  template (family resemblance with `_docs/<product>-brief-v4.html`).
- `framework/templates/product-bootstrap/sections.json` — section taxonomy
  (minimal 8 + extended 4). Single source of truth for the section ids,
  titles, and seed prompts.
- `tests/warpos/product-bootstrap.unit.test.js` — 49 assertions covering
  slug regex, sanitization, coverage QC, HTML escape, end-to-end MD/HTML
  emission, coverage failure mode, and re-run versioning.

### Paths registry

Two new keys in `framework/paths.registry.json` (regenerated into
`.claude/paths.json`, `scripts/hooks/lib/paths.generated.js`,
`schemas/paths.schema.json`, etc.):

- `paths.briefs` — `_docs/briefs` — output root for product briefs.
- `paths.briefsCurrent` — `_docs/briefs` — points at the most-recent slug
  emitted by `/product:bootstrap`. Updated on each successful run.

### TRACE events

Three new event types emitted to `paths.eventsFile`:

- `brief_started` — once per run, after CLI parsing. Captures slug, section
  set, docx backend, output dir, rerun policy, rerun-detected flag,
  pandoc-present flag, started-at ISO timestamp.
- `section_completed` — one per section in the active set. Captures
  section id, index, word count, source turns, status (`drafted` or
  `skipped_declined` or `skipped_disabled`), elapsed ms from `brief_started`.
- `brief_emitted` — once per run, at the end. Captures slug, output dir,
  per-format status, format counts, rerun action, paths registered flags,
  total elapsed ms, outcome (`success` | `partial` | `failure`).

No section body text or raw operator answers appear in any event — only
counts, ids, statuses, and timing. Emission is fail-open per `trace.md`.

## Operator-facing changes

Run `/product:bootstrap` early in a new project. The skill greets, asks
4-8 focused questions covering the required sections, drafts each section,
runs coverage QC, then writes the outputs and registers the paths keys.

```
/product:bootstrap                                  # defaults
/product:bootstrap --slug my-project                # explicit slug
/product:bootstrap --section-set extended           # 12 sections instead of 8
/product:bootstrap --docx-backend pandoc            # strict pandoc (exit 5 if missing)
/product:bootstrap --docx-backend none              # MD + HTML only
/product:bootstrap --rerun-policy overwrite         # replace without history
```

Re-runs default to versioning the prior brief under `<slug>/history/<ISO>/`.
DOCX is opt-in via pandoc detection — if pandoc is not on PATH, the run
still succeeds with MD + HTML and prints install hints.

## Compatibility

- No breaking changes to existing skills, hooks, or schemas.
- Path registry version bumped from v4 to v5 (additive — two new keys, no
  removals).
- DOCX backend is `auto` by default — fails open to MD + HTML if pandoc is
  not installed.
- Cross-platform: tested on Windows; pandoc probe uses `where` on Windows
  and `which` elsewhere.

## Downstream consumers

The brief is intended to feed:

- `/sprint:plan` — consume `paths.briefsCurrent` for product context.
- `/oneshot:start` — preflight can index the brief by stable headings.
- Onboarding / project READMEs — link to the brief or surface a "Start
  here" callout when an existing entry point exists. v0.5.1 ships the
  skill; consumers wire it on their own schedule.
